# 制作经验与参考使用

## 先拆清四件事

把时长、内容、画面文字、视觉风格分别记录。脚本描述需要表达的意思，不自动等于要逐句显示的字幕；参考片描述画风，不自动要求复刻同一段动画。本次价值总结的结论是：使用真实界面、保留浅色青蓝配色、只放大标题，把变化集中在整体移动和遮罩转场。

需要立体物体与需要「AE 风格转场」是两个独立选择。先用少量预览帧确认方向，再做长时间渲染。对本次平面插入片段，三维任务路径/聚焦镜/书签方案已经被替换；它们仍作为可研究的历史代码保留，不作为该需求的推荐方案。此前品牌片头和海洋片尾的三维研究仍有各自的用途。

## 用真实素材保持可信

- 产品页面使用真实截图、真实录屏或其裁切，避免动画重新绘制出不存在的 UI。
- 静态截图不要冒充真实交互。需要选项变化时使用实际操作片段；不能提交的动作只展示已有选择状态。
- 截图中的本来文字可以保留，但额外说明以大标题和少量关键词为主。
- 局部放大时以内容可读为标准。完整画面里“看起来没被裁切”不代表放大后的两个选项仍完整，须检查实际编码帧。

## 转场由连续关系来组织

**同一视觉区域扩展。** 先出现截图卡片，再让这个区域改变位置、大小和圆角，承接桌面录屏。对应 `PremiumMotion` 的桥接片段与 `FlatEntry` 的 `SharedCarrier`。图像淡入可辅助匹配，但应避免像翻幻灯片一样只做不相关画面交叉淡化。

**连续横向舞台。** 多个场景预先排在同一个平面画布中，用统一缓动移动，读者能理解上一场景去了哪里。对应 `BrandIntros.Journey` 与平面 A。位移快时短暂加入少量模糊，停留时恢复清晰。

**遮罩承担切换。** 圆角整屏遮罩适合明确的章节变化；分条错峰移动更活泼，适合短段落。重要文字应在遮罩结束后有充分稳定时间，不要把整段都塞满转场。

**首尾帧桥接。** 把录屏的第一帧和最后一帧提取为图片，分别用于入场和离场，可避免静态画面与视频开始播放时突然跳变。原生录屏 30 fps 与图形层 60 fps 可以共存，但 60 fps 时间线不会增加原生操作的真实采样信息。

## 时间与成片校验

时间码最后两位通常是帧；先问剪辑工程帧率。比如 `01:37:20 → 01:51:13` 的帧差是 `14×fps−7`，60 fps 是 833 帧，30 fps 是 413 帧，不能一律当作 14 秒。代码在 `studies/value-summary/config.mjs` 中集中计算，渲染和校验共用，防止导出参数改了而校验仍写死。

同一批对比方案应使用相同内容、时长和导出规格，把比较重点留给动画。交付包括视频、海报、检查帧和参数清单。单看 Remotion 预览不够，应对实际 MP4 完整解码并重新抽帧。

## 三维制作经验

Blender 几何、灯光和相机由 Python 生成，Remotion 负责排版、品牌文字与最后的真实产品画面。三维源帧率和最终时间线帧率要分别记录。大规模渲染先选少量关键帧检查，再启动完整帧序列；已有帧时优先重新编码，不重复计算几何。

海洋段落采用程序化波浪与人为编排的水花/气泡，适合确定时长的宣传片，但不应描述为经过物理流体求解的模拟。保存 Blender 工程时打包贴图，方便本地继续编辑；打包后的工程可能包含私人截图和文字，因此不默认公开。

## 参考来源与复用边界

- [awesome-opus-5.5-video-prompts](https://github.com/Li-Evan/awesome-opus-5.5-video-prompts) 与其 [showreel 文字案例](https://github.com/Li-Evan/awesome-opus-5.5-video-prompts/blob/main/prompts/showreel.md)：历史制作记录将其用于同一视觉区域的变形、连续构图和文字节奏研究；当时部分嵌入视频不能播放，不能声称已观看全部视频。
- 用户提供的 Anchor 参考视频：用于观察浅色背景、青蓝点缀、标题层级和截图构图；参考文件本身不上传。
- 仓库自身 `PageCam`、`KineticText`、`PremiumMotion`、`BrandIntros`：作为可追踪的镜头、缓动和转场来源，后续方案应优先复用清楚的已有实现。

引用参考是在说明设计来源，不表示相关第三方代码、视频或素材已取得再分发许可。公开示例应使用仓库已有公开演示内容或自行提供可发布素材。
