## 真实界面素材是怎样形成的

采集与时间记录留在本地 `RealCapture/2026-09-30`。公开仓库保留以下流程知识，不复制含本机路径与演示状态信息的原始日志。

1. 手机总览来自模拟器真实截图。原静态页面录屏只有单帧，另一段启动录屏出现空白，因此未被当作有效操作视频。
2. Mac 通过实际操作采集 122 张窗口帧。原始记录首帧在 0.111 秒，末帧在 177.291 秒，不能把这 122 张图简单解释成均匀采样的高帧率录屏。
3. 剪辑记录为每张图保留独立时长，删去长等待后时间线为约 18.233 秒。编码为 30 fps 只统一播放采样，不会创造更多真实交互细节。若重建，应使用每帧的 `duration`，而不是把每张图片固定播放 1/30 秒。
4. 原宣传片再截取整理后片段的 7.5–16 秒，使选择动作在设备入场之后发生。替换素材时，操作节点与入场节点也要一起校对。
5. 卡片、决策提示使用真实截图裁切；首尾桥接图从同一个录屏派生。不要同时维护互不对应的截图和录屏版本。

实际动作包括任务切换、打开待决策详情、选中 A、返回工作区和查看阻塞任务。该段没有提交决策；成片文案不能把“选中”说成“已提交”。本轮未发现独立保存的原始 CUA 采集程序，不能把时间日志当作已收录的完整自动采集脚本。

## 补收的 macOS 抽帧工具

[`scripts/inspect-video.swift`](../scripts/inspect-video.swift) 源自提交检查目录里的临时 Swift 脚本。现在接受视频、输出目录和任意检查时间，记录请求时间与实际抽帧时间，并正确应用视频方向信息。适合没有 FFmpeg 命令的 macOS，也适合对已编码成片做第二种方式的抽帧检查。需要 macOS 13+ 和 Xcode Command Line Tools。

```sh
swift scripts/inspect-video.swift input.mp4 out/inspection 0 4.5 9.9
```

输出目录必须为空或不存在；时间必须位于视频范围内。图片最长限制为 1280×720 范围，检查构图与标题，不替代原分辨率像素验收。`inspection.json` 只记录输入文件名，不记录本机绝对路径。抽帧成功不代表完整解码检查通过。

本地新版实际抽帧检查覆盖平面 A 成片的 0、6.5、13.85 秒。受限执行环境可能禁止系统视频解码，需要在允许 AVFoundation 解码的本地环境运行。
